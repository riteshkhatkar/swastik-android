01 — Executive Summary & Project Purpose

Strategic rationale, operational benefits, and architectural decisions

Page 2 of 12
🎯 Core Project Objective: Transition the Swastik Hospital Management System from a browser-dependent web portal into a fast, native Android app for staff tablets and smartphones. All 60+ clinical and administrative features will remain 100% synchronized with the live hospital database.

🏥 About Swastik Hospital Platform

Swastik HMS is a specialized psychiatric hospital platform governing all inpatient (IPD) and outpatient (OPD) care. Current operations include emergency admission protocols, rounding logs, ICD-11 psychiatric diagnosis tracking, SOAP clinical documentation, ward bed allocation, diagnostic laboratory workflows, and multi-tier medical billing.

While the existing React 19 web application is fully operational, hospital staff face mobility barriers carrying laptops during ward visits and rounds. The Android migration unlocks bedside access for doctors and field staff.

🔒 Non-Negotiable Architecture Decision

The FastAPI + MongoDB backend remains 100% UNCHANGED.

The Android application functions purely as a new native client consuming the existing REST API endpoints over secure HTTPS. This eliminates any risk of backend regressions, database migrations, or downtime for ongoing hospital operations during the 30-day mobile buildout.

Shared Live Database: Web portal users and Android mobile users simultaneously interact with the same database records in real time.

Business Impact & Operational Advantages

⚡
Bedside Mobility

🔔
Instant Push Alerts

📶
Offline Resiliency

Ward staff review cached records and schedules even during basement or WiFi dropouts.

📲
WhatsApp PDFs

Prescriptions and lab receipts are shared directly with patients over WhatsApp in one tap.

Curated Technology Stack & Industry Rationale

🚀 React Native + Expo 51

Shared React logic, zero Java/Kotlin boilerplate, reliable hardware APIs (Camera, Biometrics, Filesystem), and zero build-machine dependency via EAS Cloud.

🗺️ Expo Router + React Nav v6

File-based routing matching modern Next.js patterns. Native stack back-behavior and custom bottom tab bars for each of the 6 hospital roles.

🔄 Zustand + React Query v5

Zustand manages lightweight global auth states. React Query provides automated background re-fetching, cache invalidation, and offline resilience.

🎨 NativeWind (Tailwind Mobile)

Enables identical TailwindCSS utility classes from the web app. Eliminates the need to handcraft StyleSheet objects from scratch.

💳 react-native-razorpay

Official Native Android SDK opening embedded UPI apps (GPay, PhonePe, Paytm) and card sheets with cryptographic HMAC verification.

📊 Victory Native + expo-print

Victory Native renders fluid SVG revenue charts. Expo-print compiles HTML strings into vector PDF documents ready for WhatsApp dispatch.

Security & Data Privacy Framework

🔐 Hardware-Backed Token Storage:
Session tokens are saved exclusively using expo-secure-store utilizing the Android Keystore system. Tokens cannot be extracted even if the device is plugged into a PC.

🌐 Zero Hardcoded Credentials:
API URLs and Razorpay Key IDs are injected via .env files with the EXPO_PUBLIC_ prefix. The .env file is strictly excluded from version control via .gitignore.

📋 Minimal Local PHI Retention:
Patient health information is held temporarily in volatile memory by React Query and purged automatically upon application logout. No medical records are written to unencrypted storage.

🛡️ Cryptographic Payment Settlement:
Payments are never verified locally on mobile. The mobile app receives Razorpay response tokens and routes them to the FastAPI backend for SHA-256 HMAC signature verification.

Frequently Asked Questions

Q: Does the website stop working when the Android app is deployed?
A: No. Both the web portal and Android app operate simultaneously connected to the same live FastAPI backend and MongoDB database.

Q: Can doctors use their personal Android phones safely?
A: Yes. All data travels over HTTPS, session tokens are hardware encrypted, and biometric unlock prevents unauthorized device access.

Q: How do we roll out app updates after launch?
A: Using Expo EAS Update, non-native code fixes and UI improvements can be published over-the-air instantly without requiring staff to reinstall APKs.
